ブラウザが `example.com.` へ接続するには、その名前に対応する IP アドレスが必要です。この調べ物は1台のサーバーが単独で行うのではなく、役割の違う3者が分担します。本書ではこの3者を、**スタブリゾルバー**、**フルリゾルバー**、**権威 DNS サーバー**と呼びます。

以降の章では「誰が何をするか」を区別して説明します。そのための語をここで決めます。

## 依頼する側 - スタブリゾルバー

スタブリゾルバー（stub resolver）は、OS に組み込まれた小さな部品です。アプリケーションから「この名前の IP アドレスを教えてほしい」と頼まれると、その依頼を設定済みの問い合わせ先へ送り、返ってきた答えをアプリケーションへ渡します。

スタブリゾルバーは名前解決を自分では行いません。ルート DNS サーバーがどこにあるかも、目的のドメイン名を誰が管理しているかも知らず、階層をたどる処理は持っていません。持っているのは、問い合わせ先のアドレス（`/etc/resolv.conf` に書かれた `nameserver` など）だけです。

## 答えを探す側 - フルリゾルバー

フルリゾルバー（recursive resolver / 再帰リゾルバー）は、スタブリゾルバーからの名前解決要求を受け取り、答えが得られるまで権威 DNS サーバーへ問い合わせる役です。そのことから、「キャッシュ DNS サーバー」とも呼ばれます。Unbound はこの役を担うソフトウェアです。

フルリゾルバーは、最初から答えを持っているわけではありません。複数の権威 DNS サーバーに順に問い合わせ、返ってきた情報を頼りに次の問い合わせ先を決めます。一度得た情報はキャッシュに保存し、次に同じ名前を聞かれたときはそこから回答します。

スタブリゾルバーから見ると、フルリゾルバーは「頼めば最終的な答えを返してくれる相手」です。しかし、その裏で何回問い合わせが起きたかは、スタブリゾルバーには見えません。

## 自分の担当範囲だけを答える側 - 権威 DNS サーバー

権威 DNS サーバー（authoritative DNS server）は、自分が管理する範囲の情報を、外部に問い合わせずに答えられるサーバーです。`example.com.` の権威 DNS サーバーは `example.com.` の情報を答えますが、`example.net.` については答えません。権威 DNS サーバーは自分の担当範囲の外を知りません。

担当範囲の外について聞かれたとき、権威 DNS サーバーはエラーを返すとは限りません。問い合わせた名前を含む下位のゾーンが別の権威 DNS サーバーに委任されている場合、「その先はこちらの権威 DNS サーバーに問い合わせてください」という応答を返します。これを**委任応答**（referral）と呼びます。委任応答は最終的な答えではなく、次に問い合わせる先の案内です。

フルリゾルバーが複数の権威 DNS サーバーに順番に問い合わせるのは、この委任応答をたどるためです。実際の経路は[名前解決とキャッシュ](/ja/01-dns-minimum/03-resolution-cache/)で扱います。

## 三者の関係

名前解決の依頼は、次の向きに流れます。

- アプリケーション ➡ スタブリゾルバー: 名前に対応する IP アドレスを頼む
- スタブリゾルバー ➡ フルリゾルバー: 名前解決要求を1回送る
- フルリゾルバー ➡ 権威 DNS サーバー: 答えが得られるまで複数回問い合わせる

戻りはこの逆です。権威 DNS サーバーからの応答はフルリゾルバーが受け取り、フルリゾルバーが組み立てた最終的な答えだけがスタブリゾルバーへ返ります。スタブリゾルバーが自分でルート DNS サーバーをたどることはありません。

## 再帰的問い合わせと反復的名前解決

フルリゾルバーは「再帰リゾルバー」とも呼ばれますが、フルリゾルバー自身が権威 DNS サーバーへ送る問い合わせは再帰的問い合わせではありません。

**再帰的問い合わせ**は問い合わせの種類を指し、DNS メッセージの RD（Recursion Desired）ビットが1の問い合わせのことを言います。スタブリゾルバーがフルリゾルバーへ送る問い合わせがこれにあたり、「あなたの側で最後まで解決してほしい」という依頼を意味します。RD が0の問い合わせは**非再帰的問い合わせ**と呼びます。

一方、フルリゾルバーは、ルート DNS サーバーから委任応答をたどりながら、権威 DNS サーバーへ順番に問い合わせます。この処理を**反復的名前解決**（iterative resolution）と呼びます。フルリゾルバーが権威 DNS サーバーへ送る問い合わせでは、通常 RD を立てません。

つまり、スタブリゾルバーからフルリゾルバーへの問い合わせは再帰的問い合わせであり、フルリゾルバーがその要求に応えるために行う処理は反復的名前解決です。本書では、この2つを区別して書きます。
