## 「実装から見ると」コラム

コラムは独自の `column` Directive で書きます。web では専用の枠へ、Pandoc では PDF・EPUB 用の枠へ変換します。GitHub 上では `:::` がそのまま見えますが、これは許容しています。

````md
:::column[Unbound 1.26.0]
`local-zone` の設定リストは先頭挿入で構築されるため、重複した名前を書くと、
最後に読まれた行が先頭に来ます。
:::
````

上の記法は、次のように表示されます。

:::column[Unbound 1.26.0]
レキサは `\.` を 1 トークンとして扱い、引用符を外すだけでエスケープを解きません。そのため二重引用符内の `\"` は RR パーサーへ 2 文字のまま渡り、リテラルのダブルクォートと解釈されます。

該当箇所は `util/configlexer.lex` と `services/localzone.c` です。
:::

守るルールは次のとおりです。

- 開始行には **必ず 3 桁のバージョン**を `:::column[Unbound 1.26.0]` の形で入れる (book.md §4.3)
- 1 コラム 400〜800 字、1 章あたりの本数は章仕様の上限まで
- コラムの中に見出しとコードブロックを置かない。実測出力とコマンドは本文に置く
- コラムを飛ばしても正しく設定できる状態を保つ
- 名称は「実装から見ると」で固定する。種別を増やさない

バージョンの書き忘れ、本文が空、閉じ忘れは `pnpm build` の先頭で走る `pnpm check` がエラーにします。本数と文字数もここで検査します。

コラムの中に注意書きを入れるときは、外側のコロンを 1 つ増やします。同じコロン数で入れ子にすると、内側の `:::` で外側のコラムまで閉じてしまいます。

````md
::::column[Unbound 1.26.0]
本文

:::note
コラムの中の注意書き
:::

本文の続き
::::
````

## 注意書き

役割は style-guide.md §16 で固定しています。注意書きには Starlight 標準の Aside の記法を使い、種別は `note` / `tip` / `caution` / `danger` の 4 つに限ります。それ以外の種別 (`:::warning` など) は `pnpm check` がエラーにします。

````md
:::caution[重複した `local-zone` は checkconf を通る]
本文
:::
````

タイトルを省略すると、種別の既定のタイトルになります。

:::note
補足、バージョン差、知らなくても先へ進める情報を書きます。
:::

:::tip[`unbound-control` を使う]
運用や確認を楽にする実用的な方法を書きます。
:::

:::caution[設定は通るが意図どおりに動かない]
期待しない動作になる可能性がある場合に使います。「注意してください」で終わらせず、何が起こるのかを書きます。
:::

:::danger[外部からの問い合わせを受けたままにしない]
名前解決の停止、情報漏えい、重大なセキュリティ低下につながる場合に使います。
:::

## 設定とコマンド

設定例には、そのページで説明していない項目を混ぜません (style-guide.md §13)。

```conf
server:
    interface: 127.0.0.1
    local-zone: "home.arpa." static
    local-data: 'nas.home.arpa. 3600 IN A 192.168.1.10'
```

実行例と出力は分けて書きます。出力は読む箇所を本文で示します。

```console
$ dig @127.0.0.1 nas.home.arpa A +noall +answer
nas.home.arpa.		3600	IN	A	192.168.1.10
```

## 表

横に長くなりすぎる表は、箇条書きか複数の表に分けます。

| type          | 一致する名前への応答 | 一致しない名前への応答 |
| ------------- | -------------------- | ---------------------- |
| `static`      | ローカルデータ       | NXDOMAIN               |
| `transparent` | ローカルデータ       | 通常の解決へ進む       |
| `nodefault`   | —                    | 通常の解決へ進む       |
